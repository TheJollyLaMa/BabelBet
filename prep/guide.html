Prepare a Decent bridge

BabelBet retains its historical name, not its old wagering runtime. Participation is free. This is a preparation workspace, not a game, learning tracker, provider client, payroll wallet, or deployed contract application.

About & bunny-hop orientation

  1. Welcome: explore preparation without an account or wallet.
  2. Shared head: the left ankh explains steward gates; the right opens a private local profile. The title opens About.
  3. Privacy: save in tab memory or explicitly remember in this browser; export/import validated plaintext JSON locally. Never enter secrets.
  4. Accepted work: suggest translations, accessible design, documentation, permission research or offline tests; await steward review.
  5. Music or quiet: radio starts unloaded. Loading the pinned DBuskRadio module requires consent; playback requires another Play click.

The in-app tutorial works using keyboard buttons and Escape, with reduced-motion support. It has no score, account, prize or provider request.

Free participation, accepted work & receipts

No purchase, wager, stake, wallet connection or provider account is required. Public issues coordinate scope: #2 experience, #3 payroll / etiquette, #4 oversight. A suggestion or merged PR is not an automatic promise of payment.

Ask the steward to establish a private contributor-registration channel. Submit only the minimum payout identity needed, with consent; do not post payout addresses, sensitive personal information, API keys or wallet seeds in public issues or profile exports. The current app does not collect payout registration and there is no copied contributor roster.

A steward defines accepted work and any future budget before accrual. Existing Decent payroll logic is adapted for accepted-work merge accrual, queue validation and settlement receipts, but remains inactive: accounts/assets/queue are empty; no router, RPC, budget, wallet or deployment is configured. Workflow environment approval, a named steward, explicit repository activation and reviewed configuration are all required. None activates provider access or wagering.

Receipt settlement records an already-confirmed Base PayrollPaid event from a configured router. It verifies network, successful receipt, two confirmations, canonical block and exact fund/asset/recipient/amount/work/repository/contributor hashes. It does not send a transaction. Receipt permanence and payout-address visibility must be disclosed before private registration becomes a public on-chain payment record.

Local privacy & optional wallet

Profiles contain only version, nickname, languages and notes. They start in tab memory. Explicit browser storage may expose them on a shared device. Clearing removes the app's copy; downloaded files and browser backups are your responsibility. Imports reject unknown fields, malformed data and files larger than 64 KiB. Exports are plaintext, not encrypted or public IPFS backups.

The actual pinned DecentHead EIP-6963 wallet session is optional. A connection requests account access and Base network through the visitor's wallet; no signing, transfer, ENS lookup or authorization is performed. Disconnect forgets this app's session, not the extension's permission. Revoke permission in wallet settings if desired. Wallet state is never included in profile exports or sent to DBuskRadio.

The actual shared IPFS host adapter opens working local-profile backup/restore controls and reports public pinning/rewards unconfigured. Shared facade methods remain unchanged. A documented host-only component adaptation hides/disables generic provider forms; no browser API keys are accepted. Public publishing requires a separate reviewed capability, approved public payloads, explicit consent and restrictive CSP configuration. Private profiles are never published automatically. An assistant is not enabled.

Strict future provider etiquette

All official and unofficial Duolingo access is disabled now. No endpoint probing, scraping, credentials, unofficial wrappers, requests, live tests, refresh loops or outage fallbacks are supported. Historical source cannot be enabled by flags.

  1. Permission first: obtain written provider permission / documented official authorization, confirm terms, licensing and lawful purpose; steward sign-off and explicit participant consent are mandatory. Public accessibility is not permission. No reverse-engineered or unofficial client fallback.
  2. Minimum data: document each required field, purpose, retention/deletion rule, identity boundary and consent revocation. Never expose browser keys or borrow account credentials. No private contributor data goes to provider or AI systems.
  3. Rate limits: a future proposal must specify explicit finite provider-approved per-user/global request and concurrency limits. Default is zero until approved. No polling without separate consent, and no production data in CI.
  4. Caching: define provider-permitted TTL, cache keys, consent/account isolation, stale indicators and deletion. Do not cache secrets or private responses publicly. No IPFS publication of participant data.
  5. Backoff: honor Retry-After; capped exponential backoff with jitter and a finite retry budget. Never retry authentication/permission failures. Circuit-break repeated failures and stop on revoked access.
  6. Outages: display unavailable, stale or error states truthfully. Never invent activity/results or settle claims from missing data. No unofficial fallback, bypass or background recovery without renewed approved consent.
  7. Acceptance: use deterministic offline fixtures, blocked-network tests, permission review and an explicit future code review. A provider proposal requires a separate scope decision; this preparation branch contains no game, lifecycle, oracle or contract implementation.

Optional shared-helper parity

DecentBusking's committed agent-service/server.mjs, model.mjs, routing.mjs and tests are a future server-side boundary lead, not an enabled assistant. Any future adaptation needs authentication, consent, finite server-side budgets, redaction, explicit unavailable states and offline tests.
